# Changelog

### 2.0.0

KitchenSink4XL 2.0 regroups the tool surface. Read the breaking changes first, then [`docs/surface_map.md`](docs/surface_map.md), which lists every 1.2.5 tool beside its replacement.

**Breaking changes**

- **Seven grouped tools replace the 69 flat tools of 1.2.x.** The tools are `xl_read`, `xl_edit`, `xl_format`, `xl_structure`, `xl_workbook`, `xl_app` and `xl_help`. Each takes `{op, args}`, and 69 operations sit behind them. A call that used to be `set_cell(...)` is now `xl_edit` with `op: "set_cell"`. Every released operation survives except the two below. The `migrate-from-v1` recipe in `get_workflows` and `migration/v1_to_v2.json` carry the same routing map.
- **`enable_tools` and `disable_tools` are gone.** Every operation is present from the first message, and the whole tool list costs about 5.5k tokens at startup (1.x: about 15.5k for the lite core, about 25.8k with everything on). Their rows in the map have no target.
- **Old launch settings no longer stop an upgrade:** an old default such as `KS4XL_MODE=lite` is ignored with a one-line notice, and a setting that locked the tools still stops the start with a message naming what to use instead.
- **Values and arguments are validated.** `xl_help` returns the arguments and a worked example for every operation. Conditional-format and validation values are snake_case (`greater_than`, `last_7_days`, `text_length`), and `manage_chart` takes `at_cell`; the old spellings are still accepted.
- **`set_filter` counts rows under new names.** In `changed.filter`, `data_rows_visible` and `data_rows_hidden` replace the `rows_shown` and `rows_hidden` of 1.2.x. Both count data rows only, and the result says the header row is not counted.
- **`recalculate` no longer has a `formulas` engine.** The pure-Python engine is removed; recalculation needs Windows with Excel (`engine` `com` or `auto`), and `engine="formulas"` is refused with that next step. Reads still label each cached value.
- **No `xl_app` operation lets Excel reach the network unless asked.** Excel recalculates a workbook as it opens when the workbook asks for it, and workbooks written by other tools, or edited by this server, ask.
  - **What is refused.** Every operation that opens a workbook in Excel (`recalculate`, `com_goal_seek`, `com_export_pdf`, `com_render_sheet`, `com_convert_format`, `com_autofit`, `com_save_with_password`, `com_manage_pivot`, `com_set_sparkline`, `com_validate_opens_clean`) now refuses a workbook whose formulas fetch from the network as Excel calculates them (`WEBSERVICE`, also inside `FILTERXML`, `IMAGE`, `STOCKHISTORY`, `TRANSLATE`, `DETECTLANGUAGE`, `COPILOT`, `RTD`, the `CUBE` functions and Python in Excel), in a cell, a defined name or a conditional-format or validation rule, or that has external data connections. The refusal, `FORMULA_REJECTED`, names each place and function, and comes before Excel opens the workbook.
  - **Allowing it.** Each of these operations takes `allow_network=true` to let Excel make those requests. The refusal tells the AI to ask the user first, and an operation that ran with `allow_network=true` on a workbook that can reach the network says so in its result (`network_allowed: true` and a `network_note`); `recalculate` and `com_goal_seek` also list the places in `network_reach`. The values cached from the last calculation stay readable either way. The `verify_com` check of a save does not open such a workbook either; the save stands on the file check and says so.
  - **How each file type is checked.** `.xlsx` and `.xlsm` workbooks are checked from the file, CSV, OpenDocument (`.ods`) and other text files from their text, and `.xlsb`, `.xls` and encrypted workbooks by Excel itself with calculation turned off.
  - **What the check reads.** The check reads every part of a workbook file with an XML parser, and its raw text as well, so a function name counts however the file spells it (after a namespace in an OpenDocument file such as `COM.MICROSOFT.WEBSERVICE`, or written with an XML character reference, a comment, a processing instruction, a CDATA section or UTF-16 text) and wherever in the file it sits. For `.xlsx` and `.xlsm` workbooks it decides how to read each part from the part's content type, never from its name or its first bytes. Pictures and other binary parts are not parsed, but their bytes are searched too.
  - **When the check cannot be sure.** When the check cannot read a file with certainty, it refuses it the same way and says why: a part whose stored checksum does not match, XML that a parser rejects, a part in an encoding other than UTF-8 or UTF-16, a part with no content type or with one the check does not know, a part the workbook loads as XML whose content type says otherwise, two names for one part, a relationship that points at nothing, or a file over 1 GB unpacked, which is too large to read in full. The same holds when Excel's own look at a `.xlsb`, `.xls` or encrypted workbook cannot read something it needs (the target of a defined name, the data connections, the formula of a conditional-format rule): that counts as unread and refuses, never as nothing found. `allow_network=true` opens such a file too.
- **`xl_app` opens workbooks with macros turned off.** The server's hidden Excel now opens every workbook with Excel's automation security set to disable macros, so a workbook's VBA code, its auto-run macros included, does not run during a recalculation, an export or any other `xl_app` operation. A workbook with an Excel 4.0 (XLM) macro sheet, whose macros that setting cannot turn off, is refused before Excel starts, and `com_validate_opens_clean` reports it as not opened. The file tools still read and edit such a workbook without running anything.
- **A workbook whose XML declares a document type is refused.** When any XML part holds a document type declaration (`<!DOCTYPE ...>`), every operation that opens the workbook refuses it with `UNSUPPORTED_CONTENT` and one sentence that names the part, before anything is parsed. The file is not changed. Excel never writes such a part and does not open such a workbook. Before, an entity it declared could appear as cell text or a number format, or vanish from a name or a note, and an edit saved the declaration back into the file. If another program made the file, save it again from that program as an Excel workbook.
- **A workbook whose ZIP package names a part twice is refused.** A repeated part name, or two names that differ only in capital letters, is refused with `UNSUPPORTED_CONTENT` when the file is opened. Excel does not open such a file either. Before, reads showed the last copy, an edit saved both copies back, and a name in two cases made an edit fail its own check.
- **A decompression bomb is refused before it is unpacked.** When parts compressed at more than 100 to 1 add up to more than 128 MB, the workbook is refused with `UNSUPPORTED_CONTENT`, decided from the ZIP directory alone in well under a second. Before, a file of about 1 MB that unpacks to 1 GB was read in full and could need several GB of memory. Typical workbook content compresses at 4 to 30 to 1 and is not counted, however large.

**Added**

- **Update notices.** At most once a week, after you use a tool, the server checks PyPI in the background. When a newer version exists, your AI app shows a short notice with Update now and Not now, if the app supports one and the server runs through uvx or the Claude Desktop extension. Otherwise your AI mentions it once and can update it for you if you agree (`xl_app` `update_now`). It never downloads or installs a new version unless you choose Update now in its notice or ask your AI to update it. Update now refreshes a `uvx` install, or downloads and checks the new Claude Desktop bundle and opens Desktop's own install window; a `pip` or `uv tool` install gets the exact command to run. `update_notices` turns the notices on or off from any app, `KS4XL_UPDATE_NOTICES=off` turns them off and `KS4XL_UPDATE_CHECK=off` turns the check off. `kitchensink4xl --version` prints the installed version. The Claude Desktop extension also sets `KS4XL_INSTALL_ROUTE=mcpb`, which tells the server it runs from the bundle.
- **`KS4XL_READ_ONLY=1` lists only the operations that read.** `KS4XL_FORBID` removes named tools or operations from the list and from help; `KS4XL_FORBID=xl_app` closes every route that starts Excel. `KS4XL_CALL_TIMEOUT_S` and `KS4XL_MAX_OUTPUT_CHARS` bound a call's time and reply size.
- **Cell edits keep the rest of the workbook as it was, byte for byte: printer settings, `app.xml`, shared strings, row heights, pictures, x14 validation, external links and the other parts a rewrite used to touch.**
- **A formula that returns an array (`UNIQUE`, `FILTER`, `SORT`, `SEQUENCE` and the other array-returning functions) is written as a dynamic array and spills in Excel.** It used to open as `=@UNIQUE(...)` with one value.
- **Excel's formula limits are measured and checked before saving: length, nesting depth, argument count and the compiled size of the formula.**
- **Destructive calls keep a labeled snapshot of the workbook as it was, restorable by label.**
- **Writes honor sheet and workbook protection and refuse with `PROTECTED`.** `GUARD_TRIPPED` reports a safety check you passed that did not hold. The closed error vocabulary is 21 codes, all listed in `docs/llms.txt`.
- **Every operation has a curated `xl_help` example, a call sent to the wrong tool is rerouted when that is safe, and `get_server_info` reports what the tool list costs in tokens.**
- **Reads say when cached formula results may be out of date (`cached_note`): `read_range`, `get_cells`, `get_table`, `query_range`, `export_range`, `export_file`, `get_grid_view` and `find_cells` all carry it.** Edits also name the formula results that may now be stale, including results reached through LAMBDA names, relative names and what-if data tables.
- **`get_grid_view` lists what its table leaves out.** The answer's `not_shown` gives a count for each kind and the operation that reads it: the notes and threaded comments on the cells shown, the charts and pictures on the sheet with their anchor cells, and data validations of the newer kind. Shapes, sparklines and slicers are counted too, with a note that no operation lists them and that Excel shows them.
- **Reads say what Excel shows.** `read_range`, `get_cells`, `get_grid_view` and `get_table` add `shows`, which maps each cell whose text in Excel differs from the value they return to that text, so 0.75 under the format `# ?/?` comes with `" 3/4"` and 1234.5 under `$#,##0.00` with `"$1,234.50"`. Cells that show their value add nothing. A read lists the first 100 such cells and then says more differ, and each `find_cells` match carries its own `shows`. `values: "displayed"`, the text of every cell, is now named in the help.
- **`manage_comment` list returns a threaded comment as a thread, and a new workbook starts with no author name.** A threaded comment now comes back once, with `threaded: true`, its author, its date and its `replies`, where it used to come back as Excel's placeholder note ("[Threaded comment] Your version of Excel allows you to read this...") under an author ID. The server still does not write threaded comments. `create_workbook` leaves the author and last-modified-by empty and sets the created and modified times to now, where it used to leave `openpyxl`, the name of the library that wrote the file, as the author.
- **A successful write to a workbook that has a password to modify says so.** The file tools edit such a workbook without asking for the password and keep it in place, and the answer now warns that the edit was made without it, so your assistant can tell you.
- **A plain string that looks like a number, such as `"250"`, is still stored as text, and the answer now says so: `SUM` and `AVERAGE` skip text, so send the value as a number, without quotes.** The warning is stronger when the cells beside it hold numbers. Codes with a leading zero, numerals of 16 or more digits, cells formatted as Text and `{"text": ...}` values are not flagged.
- **`get_workbook_metadata` warns when a name scoped to one sheet is defined on several sheets, because the name means a different cell on each.**
- **The server instructions tell the assistant to run `find_cells` and ask you when a value or name may be on several sheets.**
- **A refused call names the form that works.** A whole-column or whole-row reference such as `A:A` is answered with the bounded range that covers the sheet's data. A bare `insert` or `delete` is answered with the four valid actions, and a span such as `B:B` for `at` with the column letter and `count`. `set_cells`, `set_filter`, `read_range` without `location`, `manage_backups` restore with `scope` and `get_grid_view` with `values: "both"` each say what they take.

**Changed**

- **Notes you add are signed with your own name.** `manage_comment` used to sign a note with a fixed assistant name when the call named no author. It now signs with your Office user name, or your Windows sign-in name when Office has none, and the answer says which name signed and where it came from. To sign notes as the assistant instead, start the server with `KS4XL_AUTHOR=assistant`, or ask for it in one call with `author="assistant"`: both sign them "AI Assistant via KS4XL". Any other author named in the call is used as given, and an edit keeps the note's author unless the call names one.
- **An email address is never written as an author.** A call that named an email address as the author of a note (`manage_comment`) or of the workbook (`set_workbook_properties`) had it stored in the file, where anyone who opens the workbook can read it. The address is now set aside and the next name is used instead: "AI Assistant via KS4XL" when the server starts with `KS4XL_AUTHOR=assistant`, otherwise your Office user name, your Windows sign-in name or "Author". The answer names the author and where it came from in `author_source`, and says in one sentence that the address was not used, so your assistant can tell you. An Office or Windows name that is itself an email address is passed over the same way.
- **One editing core, two editions.** The Community edition, `kitchensink4xl`, carries the editing core and requires the Community license notices package, `kitchensink4-license-community`, at an exact version; the Business edition, `kitchensink4xl-business`, is built on the same core. The command names are unchanged, and upgrading with pip replaces 1.x in place.
- **Structural edits, sheet rename and delete, and table rename share one reference rewriter that follows Excel's behavior, and structured references are stored in Excel's file form.** Row heights, hidden rows and outline levels move with their rows on insert and delete.
- **A new row or column takes its neighbor's settings.** An inserted row takes the height, style and outline level of the row above, and an inserted column takes the width, style and outline level of the column to its left, as Excel's own Insert does. A hidden neighbor does not make the new one hidden. Before, inserted rows started with no settings.
- **An insert or delete that would cut a pivot table or a what-if data table in two is refused,** as Excel refuses it.
- **Inserting or deleting a sheet row through two tables side by side is refused,** as Excel refuses it, with the tables named and the way round. Inserts above or below both tables, through tables stacked one above the other, and column inserts between them still work.
- **Long answers start with their totals.** The counts and paging fields (`truncated`, `total`, `next_offset` and the like) now come right after `ok` and `file` in every answer, so a client that shows only the start of a long answer still shows how many results there are and how to get the rest. `find_cells` and `query_range` also return `next_offset` when they stop early.
- **A range that reaches the last row or column, such as a whole-column conditional format or `SUM(A2:A1048576)`, survives a row insert.**
- **Import keeps codes as codes, drops the byte-order mark and reads semicolon-separated files.** Typed values such as `{"date": ...}` and `{"text": ...}` are written as typed.
- **A number written into a date or time formatted cell is accepted at read-back.** Subnormal numbers and numbers of 2^53 (9,007,199,254,740,992) or more, in either sign, are written as asked, with a warning. For the large ones the warning says the exact digits cannot be stored as a number and to pass the value as a string with the Text number format. It starts at 2^53 itself because a client rounds a 16-digit number such as 9007199254740993 to 9007199254740992 before the call is made.
- **Text comparisons ignore case, as Excel's do.** In the `where` conditions of `query_range` and in `set_filter` criteria, `eq`, `ne`, `in`, `not_in` and the ordered comparisons now compare text without regard to case, so `eq "gizmo pro"` finds the rows that say `Gizmo Pro`. Before, only `contains`, `startswith` and `endswith` ignored case.
- **A missing workbook gets its own hint, and a fault inside the server is no longer blamed on the call.** A path with no workbook answers with the next step: check the path, or make a new one with `xl_workbook create_workbook`. An error from inside the server that the arguments did not cause is reported as `INTERNAL_ERROR` instead of `BAD_PARAMS`, and a sheet name that does not exist is `NOT_FOUND`.
- **The full rewrite carries back custom properties, customXml and SharePoint parts, `app.xml`, external links, printer settings, cached formula results, automatic row heights, sensitivity labels, the password to modify, and the saved-folder path that relative links depend on.**
- **The framework's startup banner is switched off, so its own version check cannot contact PyPI.** The server's own update check is separate, and a stable build is never offered a pre-release; see Update notices under Added.

**Fixed**

- **A workbook whose ZIP also holds directory entries is edited normally.** Entries such as `xl/` are folders, not parts, so an edit that rewrites the whole workbook (adding a worksheet, for example) no longer fails with "unexplained part loss". Reported by @TongshiWang (#10).
- **`manage_image` extract writes only plain files inside `out_dir`.** Each picture is saved directly in the folder under the last part of its name. A picture name that cannot be a plain file name there (a drive letter or other colon, a device name such as `NUL` or `COM1`, a trailing dot or space, characters Windows does not allow) stops the extract before any file is written, and the answer names the picture and the reason; saving the workbook again from Excel gives its pictures ordinary names. Two pictures with the same name both arrive: the later one gets " (2)" and the answer lists it under `renamed`. Before, such names could write outside the folder, into a hidden stream or to a device, and a repeated name wrote some pictures and then failed.
- **A file Excel cannot open is never answered verified.** The check after every save now reads each stored cell value against its cell type, as Excel reads it, and refuses a save that would leave text in a number cell or any other value its type cannot hold, an error value Excel stores only as a rich value (`#SPILL!`, `#CALC!` and the like), a formula longer than 8,192 characters or a font name longer than 31 characters. A font name longer than 31 characters is refused before anything is written. Before, an edit that rewrote the whole workbook could store a volatile formula's text result as a number (for example `=IF(TODAY()>B2,"Overdue","OK")`), and Excel could not open the file.
- **Names that point relative to their cell keep their meaning.** A defined name such as "the cell above" no longer moves when you insert or delete rows or columns, as in Excel; only its fixed (`$`) parts move. Before, it could point past the last row or at the wrong cell.
- **Formulas follow sheets whose names use other scripts.** References to sheets named with letters or digits outside A to Z and 0 to 9, such as `Données`, `売上` or `Q１`, are now followed by inserts, deletes, renames and sheet deletes, as Excel does. Renaming a sheet no longer changes a longer sheet name that ends with the same letters, and a sheet name that contains double quotes is read correctly.
- **Names that contain cell-like text are left alone.** A name such as `Q1β` or `αA1` is no longer rewritten inside formulas by inserts, deletes or copies. Before, this could leave a workbook that Excel would not open.
- **Deleting a sheet writes `#REF!` as Excel does.** Formulas that pointed to the deleted sheet now hold `#REF!`, the form Excel stores. Before, Excel opened the saved workbook only after a repair.
- **Table column names that look like cell addresses survive edits.** A formula such as `=SUM(Sales[Q1])` keeps its column when you insert or delete rows or columns, add a table row or delete another table column, as in Excel.
- **Deleting a table column turns references to it into `#REF!`,** as Excel does.
- **A sheet-column insert or delete through a table is refused with the way to do it.** Deleting the sheet column under a table column was refused as if it renamed a header, and when no formula named any column it went through and saved a table that Excel opens only after a repair. It is now refused before anything changes, with the table and its columns named and the `manage_table` action that makes the edit: `delete_column` (formulas that name the column become `#REF!`, as in Excel), `add_column`, or `to_range` before deleting the whole table. The refusal for a column inserted inside a table also says that converting the table to a range removes the table. A `delete_column` that leaves cell formulas, defined names or formatting and validation rules holding `#REF!` says so in a warning, with how many of each; `audit_formulas` lists the cell formulas. `to_range` says in a warning that the table is gone and how many formulas now use cell references.
- **References to another workbook stay put.** A reference such as `[1]Data!A1` no longer moves when you insert or delete rows or columns on a sheet of the same name in your own workbook.
- **Column settings move with their columns.** Inserting or deleting columns now moves column widths, hidden columns, outline groups and column styles with their columns, as Excel does. Before, they stayed at their old letters and landed on whatever moved there.
- **Data tables, charts, pivot tables and page breaks move with their cells.** Inserting or deleting rows or columns now also moves what-if data tables (their range and input cell), charts and pictures, pivot tables, manual page breaks, scenario input cells and the formula a table gives its next row. Before, a data table could point at the wrong input cell and show zeros.
- **Renaming a sheet or a table now also updates the formula a table keeps for its calculated columns.**
- **The name selector reads every kind of name.** A name is found in any letter case, as Excel does, and a name that is the overlap of two ranges reads as that overlap. A name that covers whole columns or rows is refused with the range that reads the same data, instead of failing with an internal error.
- **Formulas reached through names in any script are reported as possibly out of date.** After a cell edit, formulas that depend on it through a name in another script (such as `Tasa_ñ` or `売上Rate`), a name holding `?` or `\`, or a sheet's own name written with its sheet (`=Loc!LocalRate`) are now listed as possibly out of date, and Excel recalculates them on open. Before, Excel could open the workbook showing their old results.
- **Displayed values follow Excel's own text in more formats.** Reads that return displayed text (`values: "displayed"`) now round halves away from zero (0.125 under `0.00` shows 0.13), count elapsed time in whole (`[h]:mm:ss` shows 30:00:00 for 1.25 days), show fractions (`# ?/?`) and scaling commas (`#,##0,`) as Excel shows them, and follow Excel's calendar for dates in January and February 1900. Formats with conditions, digits between literals (`000-00-0000`), empty sections, General's 11-character display, `_)` spacing, dates past 9999, the 1904 date system, and day, month and era names in fifteen languages also show what Excel shows; a format with one section of conditions shows other values as General, and `[<=0]` keeps a negative value's minus. For a language whose names are not covered, the read gives the value and says which cells it could not show. A format that repeats a character to fill the column (`*`) can show a different number of characters than Excel, which fills to the column's width.
- **Displayed time at exactly half of its last unit follows Excel.** A time, date and time or duration that falls exactly on half of the last unit its format shows, such as 1.25 seconds under `mm:ss.0` or 3600.5 seconds under `h:mm:ss`, now shows what Excel shows, worked out from the number the file stores the way Excel's own clock works it out. Checked against Excel on two grids of made-up cells (13,262 and 11,748): the clock and fraction formats matched, apart from elapsed formats on very large values. `[h]:mm:ss` and `[mm]:ss` were a second off on a few date-and-time-sized durations (2 and 7 of 512 on the second grid), and a lone elapsed count such as `[ss]` shows one second off for about one in sixteen to one in seven exact half seconds. Serial 60 reads as Excel's 29 February 1900, a Wednesday, and a date before 1 March 1900 takes Excel's day name.
- **Excel's built-in format `mm:ss.0` keeps its colon.** A cell saved by Excel under that format read as `0059.5` for 59.5 seconds; it now reads `00:59.5`, as in Excel.
- **`manage_table` `to_range` keeps the formulas that name the table working.** Converting a table to a plain range left every formula that named it, on any sheet and in defined names, pointing at a table that no longer existed, and Excel opened each one as `#REF!`. They are now rewritten as plain cell references first, as Excel's own Convert to Range writes them (`=SUM(Sales[Q2])` becomes `=SUM(Data!$C$2:$C$4)`). A reference that cannot be written as the same cells, such as a `#This Row` reference outside the table or a table reference in a conditional format, refuses the conversion before anything changes and names where it stands: the cell, or for a rule its kind and the cells it covers.
- **`com_render_sheet` judges the workbook before the session.** A workbook this server refuses (a document type declaration, a decompression bomb, a part named twice, a network-reaching formula) is refused as such in a session with no clipboard too, where it used to be refused for the missing clipboard.
- **A decimal row number no longer crashes an edit.** Rows whose numbers are written as decimals, such as `2.0`, which some programs write, are read as the whole-numbered rows they are. When such a row also carries a height, the edit is refused with a plain message instead of failing with an internal error.
- **Text you write is stored as written.** Writing text no longer reuses a stored string that only looked the same, such as `Ax005F_B` when you wrote `AB`, or the character `&#x80;` when you wrote the euro sign, so the cell shows the text you wrote.
- **The first note or link on a sheet no longer breaks its XML.** Adding the first note or link to a sheet whose XML already uses the prefix `r` for something else no longer fails as malformed XML.
- **Durations read as elapsed time** (`42:00:00`, where they read as `1 day, 18:00:00`), and a date past 9999 reads as its number instead of `#VALUE!`.
- **Formulas can name table columns with spaces and parentheses,** such as `=SUM(Orders[Unit price ($)])`, and a `LET` name that matches a column name no longer changes the column reference.
- **Renaming a sheet or a table keeps every formula's last result.** An iterative model whose sheet you rename opens with the values it had, not `#VALUE!`.
- **Text with `_x` codes reads as Excel shows it.** A cell Excel shows on two lines no longer reads as `line one_x000D_line two`, `Ax005F_B` no longer reads as `AB`, and you can write such text.
- **Workbooks Excel opens without a word are read.** Workbook protection written in another letter case, and TRUE/FALSE cells stored as words, no longer stop every read and edit. The protection status now reports a password stored the way current Excel stores it.
- **A row inserted inside a table takes the table's calculated columns,** as in Excel, and so does a new table row you add without values for them.
- **`validate` names what makes Excel refuse a file:** a value its cell type cannot hold, a formula longer than 8,192 characters, a font name longer than 31 characters, or a macro part that is not a macro project.
- **Formula reads tell text from formulas.** In formula mode, `read_range` and `get_table` list the text cells that start with "=", with how to write one back as text.
- **Excel's Unicode Text files import.** `import_data` reads UTF-16 and UTF-32 files by their byte-order mark, and says so when that overrode the encoding you asked for; a file in another encoding is refused in plain words that say what to pass.
- **Inventory reads count what Excel counts:** `get_workbook_metadata` lists chart sheets, `manage_name` lists print areas, print titles and filter ranges, and `manage_conditional_format` counts the rules stored in Excel's extension block.
- **A damaged workbook is refused as damaged.** A workbook with a cell that points past its shared strings, or with a part cut off mid-way, is refused with `UNSUPPORTED_CONTENT`; it used to fail as an internal error or as a problem with your request.
- **A picture's hyperlink survives edits that rewrite the workbook.**
- **A name defined with `LAMBDA` or `LET` now calculates in Excel.** A defined name such as `term` = `LAMBDA(a,a+1)` was saved without the prefixes Excel gives these functions, so Excel read it as an unknown function and every cell that called it showed `#NAME?`. Names are now saved the way Excel saves them, measured in Excel, and a definition Excel could not use is refused. `manage_name` and `get_workbook_metadata` show a definition as you wrote it.
- **A formula that is too long is refused in the length you wrote.** Excel counts its 8,192-character limit on the formula as it stores it, with `_xlfn.` added to newer functions such as `LET` and `LAMBDA` and `_xlpm.` added to each name they declare. A formula written at 5,517 characters was refused as "13,305 characters long", a number that appeared nowhere in what you wrote. The refusal now gives the length as written and about how long a formula built the same way can be, with the stored length as the reason. It comes when the formula is written, for cells and defined names alike.
- **Starting Excel no longer fails while another KitchenSink4XL server reads its records.** Every server of a user keeps one shared record of the hidden Excels it starts. A server that read it at the moment another server wrote it made that call fail with `WORKBOOK_LOCKED`, naming a file in the temp folder, and two servers writing it at once could each lose the other's entry, leaving an Excel that nothing would end. Writes now wait for the reader and take turns, and a record that still cannot be written is logged instead of failing your call.
- **A workbook opened from another program no longer lands in the hidden Excel the server uses.** A program that opens workbooks through DDE, such as a file association that uses it, could open your workbook inside the server's hidden Excel and show it to you there. Closing the server, an `xl_app` timeout or another server starting then closed it without saving and without asking. The server's Excel now ignores such requests. An Excel that holds a workbook the server did not open, or that you can see, is never closed by the server: it is left running for you with its prompts back on, and `com_status` lists it under `left_to_user`.
- **Formulas built with `LET` and `LAMBDA` are checked against Excel's size limit to the byte.** Some long formulas with `LAMBDA`, a `LAMBDA` called where it is written such as `LAMBDA(a,a+1)(A1)`, or a `LET` that holds a range were accepted although Excel would refuse to open the whole workbook, and Excel's repair then dropped the formula. Each part of these formulas is now counted as Excel stores it, measured in Excel, including `MAP`, `REDUCE`, `SCAN`, `BYROW`, `BYCOL` and `MAKEARRAY`. Where a size could not be pinned down exactly, the check refuses a few bytes early rather than write a formula Excel might not open.
- **After a crash, a workbook you renamed or deleted is no longer recreated from an older version.** If the server stopped at the end of a save, the version from before that save could come back under the workbook's name at the next start, even after you renamed or deleted the workbook. Only a save that did not finish is undone now. An older version that is no longer needed is removed when a backup holds it, or kept beside the workbook as `<name> (kept from a save that did not finish).xlsx`. A new workbook is not created under the name of one whose older version is open in another program.
- **A crash no longer costs a backup version when another copy of the server saved the workbook in between.** A save stopped right after it replaced the workbook finishes its backup rotation at the next start. If a server that could not see the unfinished save (an older version, or another Windows user on a shared folder) had saved the workbook in between, that rotation replaced the newer `prev` backup, and the version it held was lost. The rotation now lands only on the backup it was prepared for.
- **Recovery after a crash removes only the server's own temporary files.** A damaged record of an unfinished save could name any file, and the recovery at the next start deleted it. It now removes only the temporary files the server's saves write.
- **The server starts promptly when a workbook it was saving is on a share that is offline.** A save interrupted on a network share that is now unreachable made every start wait for the network, about 20 seconds each time. Each folder now gets one second. The record is kept until the share is back, and dropped after 30 days.
- **A second server no longer stops your first server's Excel after 15 minutes.** Starting a KitchenSink4XL server ended the hidden Excel of another running server that had kept it for more than 15 minutes, and that server's call failed. It now ends only an Excel whose server has stopped.
- **Excel stopping during a save is reported as Excel stopping.** If Excel ended right after writing its copy, the call answered that Excel refused the request, with a code that told your assistant its arguments were wrong. It now answers that Excel stopped. The workbook is unchanged, and a retry starts a fresh Excel. A refusal from an Excel that is still running is still answered as a refusal, also after an earlier call's Excel has ended.
- **`create_workbook` and `copy_workbook` say in words when another program holds the file.** An overwrite refused because another program had the workbook open returned the raw Windows error text. It now answers `WORKBOOK_LOCKED` with the words an edit gives.
- **`diagnose_workbook` waits out another save.** During the last few milliseconds of another save it answered that the file was not found. It now waits, as every other read does, and says where the workbook is when a save that did not finish left it aside.
- **An `xl_app` save keeps the workbook's relative hyperlinks and links.** Excel writes a relative hyperlink relative to the folder it saves into, and its copy was written in the system's temporary folder, so once the copy replaced the workbook a link such as `Source.xlsx` pointed at a path that does not exist, while the call answered ok. Excel now writes its copy beside the workbook, where every hyperlink and external link comes out exactly as Excel's own save writes it. A workbook in a folder so deep that the copy's path would pass the 218 characters Excel can save to is refused before anything changes.
- **Saves work in a folder where you may change files but not their permissions.** In such a folder, a common setting on shared drives, every save, restore and overwrite was refused with "another program had the file open", which was not true. The save now goes through, and a workbook whose own permissions could not be kept is named in a warning. A replace that Windows still denies says so, and no longer names another program.
- **A save stopped part way no longer loses the workbook.** If the server was stopped at the instant a save swapped in the new version, the workbook could be missing from its folder, and a later save of another workbook in that folder could delete it, with `backup: false` too. The workbook as it was is now kept under a name that says so, nothing removes it, and the next change to the workbook or the next start of the server puts it back. Until then, a read of it says where it is.
- **A refused restore keeps the backup it was restoring.** A restore refused at its last step, because another program held the workbook or the folder refused the replace, replaced the `prev` backup with the current content, so the version being restored was gone and a retry answered ok without changing anything. The backups now change only once the restore went through, the refusal says why, and a restore that would change nothing says so.
- **A call made while another save swaps the workbook in waits instead of failing.** During a save the workbook's path is missing for a few milliseconds, and a call that arrived in that moment answered that the workbook does not exist. Every call now waits that moment out. Other programs may still see the path missing for a few milliseconds during a save, as with Office's own saves.
- **One server's exit no longer stops another server's Excel.** When two KitchenSink4XL servers ran for the same user, one server's exit or `xl_app` timeout ended the hidden Excel the other was using, and that call failed. Each server now ends only its own hidden Excel and those left by servers that have stopped.
- **The formula size check prices `LET`, array constants and seven more functions as Excel does.** It refused some formulas with `LET` that Excel opens, and accepted formulas with array constants such as `{1,2,3}`, or with `IMSUM`, `IMPRODUCT`, `TOCOL`, `TOROW`, `WRAPROWS`, `WRAPCOLS` or `EXPAND`, that Excel will not open. Measured in Excel, each now stops at Excel's own limit.
- **An `xl_app` save and a file-tool edit to the same workbook can no longer overwrite each other.** A file-tool edit, from this server or another one, made while an `xl_app` operation such as `recalculate`, `com_autofit` or `com_save_with_password` was saving the same workbook could be replaced by Excel's copy, and both calls answered ok. The `xl_app` operation now holds the workbook's write lock until its copy is in place, so the edit waits and is then refused with the reason, or applies on top when it comes after. If another program changes the workbook while Excel works on it, the `xl_app` call is refused and that program's change is kept.
- **Excel's copy is checked before it replaces the workbook.** The structure check, the internal-link check and the encryption check now run on the copy Excel saved, before it goes in place, so a bad save never replaces the workbook, even with `backup: false`. They used to run afterward and put the backup back, which left a bad save in place when there was no backup.
- **Excel's copy is not left behind when a save is interrupted.** A copy that an interrupted `xl_app` save left beside the workbook is removed by a later save in that folder once it is an hour old.
- **On a drive that cannot replace a file in place, a save keeps the workbook's permissions, creation date, the mark that it came from the internet and any other data stored with the file.** Some network drives cannot swap in a new version of a file, so the new version arrived as a new file without them. They are now carried over first, where the drive supports them.
- **The formula size check counts a union of references at the size Excel gives it.** A union such as `SUM((A1,B2))` takes 7 more bytes than its references, or 3 when it holds a function call or a reference to another sheet, so a formula with 2,047 references in one union saved and Excel could not open the workbook. It is now refused before saving, at the limit Excel uses.
- **An `xl_app` edit no longer shows Excel's Save As dialog when another program opens the workbook while Excel works.** Excel now saves the edit as a copy, and the copy replaces the workbook once Excel has closed it, through the same route the file tools use, so the workbook keeps its permissions, the mark that it came from the internet, its attributes and its creation date. If a program still holds the workbook at that moment, the call is refused with the cause and the workbook stays as it was. Excel's temporary copy is no longer left beside the file.
- **Two servers waiting for the same workbook can no longer both take its write lock.** When the server holding the lock had stopped, two waiting servers could both remove its lock file, and the slower one removed the lock the faster one had just taken. Both then wrote, and one edit could be lost. Only one waiting server now removes a stale lock, and a lock taken since is never touched.
- **A write-lock file that a server could not delete is always cleaned up.** If the same workbook's lock was released again just as the background sweeper finished removing the first leftover, the sweeper could forget the new one, and other servers were refused until that server wrote to the workbook again.
- **The formula size check counts each Excel function call at the size Excel gives it.** Functions with an optional or repeating argument (`SUM`, `XOR`, `VLOOKUP` and about 120 more), `IFERROR` and `IFNA`, and volatile functions such as `NOW` and `OFFSET` take more room than the check counted, so a formula with about 100 such calls beside very many cell references saved and Excel could not open the workbook. It is now refused before saving; for the 210 functions measured against Excel, the limit falls exactly where Excel's does.
- **Writing a number as text into a column or row formatted as Text no longer warns.** A whole column formatted as Text is how a sheet marks an ID or code column, and the new cell takes that format, so the "now holds the TEXT" warning was wrong there. A cell with its own number format, other than Text, still gets the warning.
- **A second server no longer waits for a lock the first one forgot to release.** When another program (an antivirus scanner, a backup or sync client, or a second server checking the lock file) had a workbook's write-lock file open at the moment a server released it, the file stayed behind. Every other server was then refused for that workbook ("being modified by another kitchensink4xl process") until the first one exited, however idle it was. The release now retries, a background sweeper removes a file it still cannot delete, and the next edit from the same server takes over a leftover of its own.
- **The formula size check counts calls through a sheet name (`S!q(1)`) and calls to a `LET` or `LAMBDA` name at the size Excel gives them.** A formula with about 1,100 calls through a short sheet name, or with calls to a `LET` or `LAMBDA` name beside very many cell references, saved and Excel could not open the workbook. It is now refused before saving. A name with sheet scope costs the same as one with workbook scope, so nothing changes for those.
- **An `xl_app` operation that writes now changes an Excel template itself.** On an `.xltx` or `.xltm` file it used to edit a new workbook made from the template and save that copy into Excel's current folder, usually Documents, replacing any file there with the same name, while the template stayed as it was. An `xl_app` save now lands on the workbook it was asked to change, or nowhere.
- **A workbook another program has open for reading is refused before Excel starts.** Many programs read a file in a way that stops it being replaced, so Excel could not save its edit and showed its Save As dialog. The `xl_app` operations and the file tools now both refuse such a workbook and name another program as the cause.
- **A formula with about 1,260 or more calls to a LAMBDA name or a user-defined function is refused before saving.** Excel could not open a workbook holding one.
- **Any edit repairs a table filter that 1.2.6 and earlier 2.0 candidates saved in a form Excel will not open.** The filter becomes the table's own filter, with the same criteria and the same hidden rows, and the answer says so. A save that would still leave that form in place fails instead of reporting success, and the `xl_app` operations refuse such a workbook before Excel starts and name `clear_filter`.
- **File edits keep what Windows stores on the workbook itself:** its permissions, the mark that it came from the internet (so Excel still opens it in Protected View), its OneDrive "Always keep on this device" and "Free up space" settings and its creation date. Every file edit used to drop them. Restoring a backup keeps them too.
- **`set_filter` stores criteria that Excel re-applies to the same rows.** Equality on a formatted number (`1,000`, `50%`, `1.50`) matches what the cell shows, text codes such as `007` and `7` stay apart, and `?` and `*` in text are matched as written.
- **A network path longer than 240 characters is no longer refused as in use.**
- **A folder that does not let you create files, and a file whose permissions do not let you read it, are named as the cause.** These refusals used to say the file might be open in Excel, with raw system text.
- **A workbook with a password to modify is refused by every `xl_app` operation that would open it for editing, with the remedy, so Excel's Password dialog no longer lands on the desktop.** Most such files are refused before Excel starts, and an encrypted one is refused as soon as Excel reports the password. Read-only Excel operations still open it. The full rewrite no longer drops that password.
- **The password to modify is found in more kinds of file: a binary `.xlsb` workbook and a workbook whose `workbook.xml` is stored as UTF-16 are recognized without Excel, and a workbook that is also encrypted is refused with the remedy when Excel reports the password.** `com_save_with_password` refuses a legacy `.xls` workbook before Excel starts, as the other `xl_app` operations that write do.
- **A workbook that another program holds open for both reading and writing is refused before Excel starts, and a workbook Excel could open only read-only is refused rather than saved over.** The refusal says "open in Excel" only when Excel's own `~$` owner file sits beside the workbook; otherwise it names another program.
- **`set_filter` on a table no longer writes a sheet filter over the table, which Excel refuses to open.** It writes the table's own filter, `clear_filter` removes the criteria and shows the rows again, and it also removes a sheet filter of that older kind, which repairs a file saved that way.
- **A formula with so many defined names or table references that Excel could not open the workbook is refused before saving.** The check counts a name and a table reference at the size Excel gives them.
- **A `.ks4xl-backups` entry that is a file instead of a folder is reported in plain words before anything is written, and no scratch file is left behind.** A few helper scratch files now carry the name the cleanup removes, so the next write sweeps what a crash leaves.
- **A table stays openable after a header write, and a path in the Windows device namespace is refused instead of hanging the call.**
- **Excel-saved files now pass the same broken-link integrity check as file saves, and a failure restores the backup.**
- **Encrypted workbooks are refused by signature before Excel starts unless a password is given.**
- **A formula whose cached result is the empty string reads as cached, not absent.**
- **A save that committed inside the time bound is never reported as a timeout, and exit waits a bounded time for calls in flight and ends nothing.**
- **A legacy query table no longer makes an edited workbook unopenable.** A table fed by a web, database or text query is dropped by any edit that rewrites the file, and the edit is refused until you pass `allow_loss=true`. With it, the query's definition and data connection went but the table still said it was a query table, so Excel refused to open the file while the answer said verified. The table now stays as an ordinary table with its cells, name, range and style, the answer says it no longer refreshes from its source, and every save and `validate` check that a table marked as a query table has its query part: an internal relationship of the query table type that reaches a real query table part. The check reads the XML itself, so it gives the same answer however the file is spelled.
- **Content hidden under merged cells is named before an edit drops it.** Excel keeps a value, a note or a hyperlink stored in a cell of a merged range other than its top-left cell, out of sight. An edit that rewrites the file lost it without a word, and moved such a hyperlink to the top-left cell. That edit is now refused with the loss named, and `allow_loss=true` accepts it. The sheet is read as XML, so the answer is the same whatever the file's spelling (single or double quotes, a namespace prefix, UTF-16, character references, cells without a coordinate).
- **A merged range's top-left cell moves with its column.** An insert or delete that moved a merged range deleted that cell with its text and link. It now keeps both, and rows that move up into a deleted merge are left alone.
- **Hyperlinks stay with their cells.** After a row or column insert or delete, a link kept its old address: it sat on a cell that no longer held its text, and the cell that moved lost it. Each link now moves with its cell.
- **A workbook saved as Strict Open XML is refused by name.** Excel opens it, but this server reads the standard format, so it read as a workbook with no sheets and an edit answered that there was no active sheet. Every read and edit now answers `UNSUPPORTED_CONTENT`, says the file is Strict Open XML, and says to save it from Excel as an Excel Workbook (.xlsx). Nothing is changed. `validate` says the same. The file is recognized from its XML, however it is spelled (any quote style, UTF-16, a namespace prefix) and wherever its root relationship points the workbook part.
- **A defined name or table name that begins like a cell reference is refused.** Excel will not accept a name that starts with an R1C1 reference, such as `R1_x`, `R2D2`, `C21_Name` or `Rc21_Name`, and will not open a workbook that carries one. The check refused only a name that was entirely a reference (`R1C1`, `R2`), so such a name was saved, verified and answered ok. Adding or renaming a name or a table to one is now refused with the reason; names like `R_x`, `RC_x` and `Q21_Name` are unaffected. For a defined name the check follows Excel exactly: the number after the R, C or RC counts only when it is a real row (1 to 1,048,576) or column (1 to 16,384), so `R0_x`, `C16385_x` and `RC0_x` are accepted, as is a name with a period right after the number (`R1.x`), and the digits of other scripts that Excel reads as digits, such as Arabic-Indic and Devanagari, count too. Table names keep the stricter check: one that begins with R, C or RC and a number is refused whatever the number, so `R0_x` and `C16385_x` are accepted as defined names but not as table names.
- **A macro-enabled template keeps its macros and its file type through an edit.** An edit of an `.xltm` file saved it as a plain template without its macro project, so Excel refused to open it ("the file format or file extension is not valid") while the answer said verified. A `.xltm` file now gets the same treatment as `.xlsm`: its macro project stays and it keeps the macro-enabled template type. Every save and `validate` also check that the workbook type stored in the file matches its extension (`.xlsx`, `.xlsm`, `.xltx` or `.xltm`), and a save that would leave them different is refused with the reason.
- **A workbook whose sheet links are spelled with percent codes reads normally.** A workbook with links such as `worksheets/sheet%31.xml` (the same part as `sheet1.xml`, and Excel opens it) read as ok with no sheets, and an edit answered that there was no active sheet. The links are now read the way Excel reads them. A workbook that lists a sheet that cannot be opened is refused by name with `UNSUPPORTED_CONTENT` and is not changed, instead of being read as an empty workbook or with sheets missing, or losing a sheet on a save. That covers a sheet whose link names no part of the file, a sheet with no relationship id or an empty one, and a sheet whose id names no relationship; Excel does not open any of them.
- **Adding a row to a table extends what covers its data, as Excel does.** A total such as `SUM(D2:D13)` over a table's column, a defined name, a conditional-format or validation range, or a chart series over the data stayed at its old size when `manage_table` added a row, when a row was inserted at the table's first data row, or when a row was inserted at its totals row, so the total missed the new row. They now grow with the table. A range that covers only part of the data, runs past the table or into another column is left as it was, which is what Excel does. A print area or pivot table source that covers exactly the table's data is not extended, and the answer says so.
- **An edit of a workbook that `validate` calls unopenable is refused.** A macro part that is not a macro project makes Excel refuse the whole file. `validate` said so, but a cell edit of the same file answered verified. The save check now refuses the edit with the same reason, and the file is not changed.
- **Editing a cell that a document property is linked to no longer gets undone when the workbook opens.** A custom document property can be linked to a cell through a defined name, and Excel copies the property's value into the cell on open. An edit of that cell was saved and answered verified, but the property kept the old value, so Excel put it back. A save that changes such a cell now writes the new value into the linked property, in the property's own type (number, text, TRUE/FALSE, date), on both save routes, and names it under `changed.linked_properties`. A value the property cannot hold, such as text for a number property, a formula, an error value or an empty cell for a number, is refused with `HAZARD_REFUSED` naming the property and the cell; `allow_loss=true` saves the edit anyway, leaves the property as it was and names it in a warning. A row or column inserted above the cell moves the cell and its name together and changes no property. A linked property is found whichever way the file writes it: the property part or the workbook part in UTF-16, a name or value in a CDATA section, or a namespace prefix. The property part is saved in the encoding it had. A date goes into a date property the way Excel writes it. The number is read as Excel numbers dates (in the 1900 date system, serial 1 is 1 January 1900 and serial 59 is 28 February 1900), and the property holds the UTC instant of the cell's date and time in the computer's time zone, so the cell shows the same value when the workbook opens. Dates are checked against Excel in time zones without daylight saving time; in a zone that has it, a date on the other side of a clock change may be stored with the wrong offset. A number before the first date of the workbook's date system (1 January 1900 or, in the 1904 system, 1 January 1904) is refused with `HAZARD_REFUSED`, and so is serial 60 in the 1900 system, which stands for a 29 February 1900 that never existed. A number outside the range of the property's type (for example `1e40` into a single-precision property), or so close to zero that the type would store it as 0, is refused the same way. Formulas are compared as written, apart from the leading `=`, so a change as small as one space inside quoted text counts as a change.
- **A shared formula with no usable first cell reads as the stored value, with a flag.** When the first cell of a shared formula is missing, or comes after a cell that uses it, no formula can be recovered, and Excel drops the formula and keeps the value when it repairs the file. `read_range`, `get_cells`, `get_grid_view` and `audit_formulas` showed the formula `=` for those cells, `get_workbook_metadata` called the workbook clean, and `set_formula` with `=` answered ok and stored the text `=`. They now return the stored value, name the cells under `broken_shared_formulas` with a note that no formula was recovered, and the hazard scan lists "shared formulas with no usable first cell". `set_formula` with nothing after the equals sign is refused by name; to store the text `=`, use `set_cell`. The `broken_shared_formulas` flag and the hazard-scan entry are raised whichever way the worksheet part is written: in UTF-16, with a character reference, or with an XML comment or processing instruction that looks like the first cell.
